## Summary
The codebase is a well-documented Toss mini-app with clear layering (types → constants → repository → hooks → pages) and a deliberate 'Pre-built component' doctrine, but it has accumulated real duplication: two competing EmptyState/LoadingState implementations, a hand-rolled haptic-feedback wrapper copy-pasted in four places, duplicated form-validation helpers, and a stale contract.ts whose types no longer match the real domain model. No circular dependencies were found, but import-path style (relative vs `@/` alias) is inconsistent even within single files.

## Issues
### Critical
- [duplication] EmptyState and LoadingState are implemented twice with different APIs: once in components/StateView.tsx (icon/title/description/action props) and again in components/common.tsx (iconName/message/ctaLabel/onCta props). Every page in the codebase (Report, SimulateResult) imports the StateView version, suggesting common.tsx's copies are dead and diverging. — Files: src/components/StateView.tsx, src/components/common.tsx / Fix: Delete the duplicate EmptyState/LoadingState in common.tsx (keep only SectionHeader there, or move it into StateView.tsx/a shared file) and update any remaining callers to the single StateView API.
- [dead_code] src/lib/contract.ts declares a full parallel domain model (User, Mission, Activity, Badge, SimulationInput/Result, RouteState as a string union, getUserDataFn, calculateStreakFn, useAppDataFn, etc.) that no longer matches the actual implementation — real code uses CreditProfile/DailyMissionLog/ScoreSnapshot and a completely different RouteState shape (a route-to-params map) defined in lib/types.ts. Having two conflicting `RouteState` types under similar names is actively misleading. — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Remove contract.ts now that all packets are implemented, or clearly mark it as historical/planning-only documentation excluded from the src type-check graph so it can't be confused with lib/types.ts.

### Suggestions

- [duplication] Amount.tsx and CountUp.tsx duplicate the exact same wrapper markup/styles (nowrap span, tabular-nums, maxWidth 100%) around Paragraph.Text — only the value-computation logic differs (static vs animated). — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract a shared `NumericText` presentational wrapper (styles only) that both Amount and CountUp render into, so the nowrap/tabular-nums styling lives in one place.
- [dead_code] Several exports have no visible callers anywhere in the provided 40 files: `cn` and `formatCurrency` in lib/utils.ts, the `MiniBar` component, and the `TossPurchase`/`TossPurchaseResult` component — none of the pages (Home, Missions, Badges, Simulate, SimulateResult, Report) import them. — Files: src/lib/utils.ts, src/components/MiniBar.tsx, src/components/TossPurchase.tsx / Fix: If these are intentionally-unused pre-built primitives for future packets, note that explicitly in a comment (as other Pre-built components do); otherwise remove them or wire them into a page to justify their presence.
- [structure] src/components/common.tsx breaks the otherwise-consistent PascalCase-per-component file naming convention (Card.tsx, Amount.tsx, StateView.tsx, etc.) and bundles unrelated components (SectionHeader + duplicate EmptyState/LoadingState) into a catch-all file. — Files: src/components/common.tsx / Fix: Split common.tsx into per-component files matching the existing naming convention (e.g. SectionHeader.tsx), after removing the duplicate EmptyState/LoadingState.
